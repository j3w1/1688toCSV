# Development

Use Node.js 24 and the workflow in [AGENTS.md](../AGENTS.md): iterate locally with `npm run try`, and run full verification once at deploy. Edit sources, rebuild explicitly, then test the generated **dist** extension. There is no watch mode.

| Command                               | Purpose                                                                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `npm run try`                         | Unit tests, development build, stage into the installed extension, reload it through CE Dev Browser and confirm library counts |
| `npm run verify`                      | Source/docs checks, unit tests, production rebuild and isolated Chromium tests                                                 |
| `npm run build` / `npm run build:dev` | Build the complete extension once into dist                                                                                    |
| `npm run test:browser`                | Test the current build with synthetic pages in a temporary profile                                                             |
| `npm run test:excel`                  | Windows Excel integration check in an unsaved workbook; restores the clipboard                                                 |
| `npm run preview`                     | Synthetic preview; `/library.html` opens the workspace                                                                         |
| `npm run screenshots`                 | Regenerate workspace and label-editor images using synthetic data                                                              |
| `npm run check:docs`                  | Validate local links, screenshots and documented commands                                                                      |

For UI changes, regenerate screenshots and check documentation after final verification. Keep the main README practical; record only necessary developer constraints here. Do not commit private orders, exports, captures, profiles or credentials.

[CI](../.github/workflows/ci.yml) routes docs-only changes to documentation checks, code to full verification, and mixed changes to both. Its stable `required` check rejects failures, cancellations and unexpected skips. Desktop Excel is tested locally, not in hosted Linux CI.

## Boundaries

Order cards keep store identity, Spanish product names and product counts in one compact `.order-card-main` block. The separate status/tag block has a larger gap above it. Preserve readable font sizes, centered icon controls and wrapping tags in both themes and narrow sidebars.

The main library sorts both order cards and product groups by canonical purchase timestamp descending, with unknown dates last and source product order retained. Packing arrangement is separate. Successful import-save notifications refresh records and detach stale row bindings; new matching orders reset Products and the Orders sidebar to the top without clearing filters or selected product keys.

Page adapters extract and validate source data. Monetary calculations use exact cents. IndexedDB stores snapshots, history, notes, import checkpoints and separate packing data. The import controller owns bounded retries and tab navigation; the library owns filtering and clipboard presentation. Add layout support in adapters and synthetic fixtures, keeping selectors out of the library UI.

Full order and product-entry IDs remain strings. Only complete snapshots that reconcile with displayed totals replace saved data. Changed data creates a retained version; notes and tags remain separate. Failed reads preserve the last good snapshot. Purchase dates describe the source order, not the time it was imported; unknown dates remain unknown until a successful refresh supplies them. Once established, purchase time stays fixed across list and detail reads.

Imports use one marked reader, trying a blank background tab (`active: false`, not auto-discardable), an unfocused window, then an active visible tab automatically if the earlier modes are refused. Reader-mode fallback does not require a separate consent action. Sign-in or verification pauses the job with `attention` identifying the reader tab; the workspace notice opens that tab and Resume clears the interruption. Preserve tabs navigated away from the importer. Existing paused jobs require explicit Resume or a new Refresh; never restart saved bulk queues automatically on workspace opening. **Open Workspace** opens the library; **Open Workspace here** refuses to replace a tab used by a running import. Dismissing an import notice hides it without deleting its job or order records.

`createReaderTab()` verifies a created tab with `tabs.get()` before checkpointing its ID; a browser may return a phantom ID for a tab it did not retain. Missing-tab errors permit the next reader-creation mode, and a missing owned reader is reopened through the controller's normal recovery path. Genuine navigation/API failures stay actionable without uncontrolled tab creation. Cleanup closes only the importer's retained reader and preserves login or user-navigated tabs; a failed refresh keeps the last good source snapshot.

#### Recorded payments and cost attribution

`payment-links.js` and its repository/editor keep already recorded payments separate from manual external charges. A target order stores reviewed `paymentLinks` with source order/optional fee-row reference, exact-cent amount, reason, frozen target entry IDs and original source amount/payable/shipping evidence. Whole-order links start with the full existing payable, including shipping. A confirmed order-wide allocation does not establish a per-feature split. New or repointed sources must share the target’s known store identity and account (`eligiblePaymentSource()`); a same-order fee row remains available when store identity is unknown. Display names alone never establish identity. The editor searches visible native radio cards for source orders and fee rows, with photos, exact grouped amounts and explicit all-goods/selected-goods choices. Reason buttons fill editable text. Empty states distinguish an absent source, no positive source amount and no other goods to receive a same-order fee; they point to another recorded same-store payment or manual Additional charges as appropriate. Repository writes enforce eligibility atomically. Existing reviewed historical references/evidence remain intact until explicitly edited or removed. The source snapshots/payables stay unchanged and are counted once; only receiving goods gain the attributed cost. A same-order fee is removed from its source row attribution before distribution to goods, preventing double counting.

Saving links atomically skips payment-source rows for packing. Linked-source membership also excludes rows from preparation and bulk label/print output independently of ordinary skip annotations; its include control stays disabled until unlinking. Unlinking restores only skips authored by that link when no newer user edit replaced them; shared source ownership transfers until the last link is removed. Duplicate/oversubscribed payments, cycles, missing/cross-account references and unavailable receiving goods reject atomically. Source money changes retain the reviewed allocation and show a review warning rather than silently redistributing. Deleting one side requires unlinking first when it would leave a reference or owned skip; deleting the complete linked set is allowed. Source refresh, exclusions and restore validate the complete resulting graph.

`paymentCostAdjustments()` receives complete records, including recursive sources. Products and preparation copy/export paths cache per-order costs. Packing exports add linked costs, effective amounts, reasons and product features when present; manual charges stay separate. Scoped packing backups declare complete financial source records in `packingScope.dependencies`, without adding their preparations to the opened packing scope. Exact dependency validation rejects unrelated orders and missing payment sources.

#### Repeat purchases and shared codes

`repeat-products.js` plans a reviewed link within one known store/account/packing month. Whole-group matching remains supported. A source group containing one variant can also link to its matching variant in an original multi-size group: radio cards identify the original target, and unmatched original variants keep their existing codes and ownership. Matching variants, sizes and features receive optional group `sharedProductId`/`sharedStoreId` and variant `sharedVariantId`. One unique account/kind/code reservation contains the source owner aliases in `members`; unrelated code collisions still reject. Preview is read-only; saving checks every preparation revision and source observation/feature snapshot in one transaction. Source quantities and financial evidence remain separate: two linked purchases of 3 and 27 pieces yield 30 labels with the same barcode.

Linked identity/code/name/variant/grouping edits require unlinking first, as do additions, removals or renames of linked product features; delay/warehouse edits remain independent. Shared identity compares normalized feature names, independent of feature keys and purchase-specific costs. Cost-only edits remain available; each source purchase keeps its own feature costs. Unlinking assigns a free code to the chosen purchase. Removal retains surviving owners, and scoped backups retain only selected aliases. Label copying deduplicates shared codes; printing sums selected source quantities/carton counts and preserves all source refs in recent print jobs. Unknown/remainder cartons still require review. Cross-month code reuse and physical mixed-carton shipment tracking remain unsupported.

`createLanguageScope(root)` owns popup language without changing `LANGUAGE_PREFERENCE`, document language or workspace listeners. Text/attribute bindings resolve against their closest scope, including nested messages and newly appended controls. Portalled child dialogs inherit their opener’s language; scopes disconnect their insertion observer on close. `getLanguage(root)` / `getLocale(root)` and scoped subscriptions feed local previews and frozen exports. Reopening a saved print job applies its language only to that print dialog. Copy-preparation columns translate headers and generated feature wording with the popup locale while preserving authored source data.

## China-store spreadsheets

The workspace supports 1688 purchases and local supplier orders through the same selection, Skip packing, Prepare, code-assignment and export workflow. A **store** can be a 1688 seller, a numbered market shop (including Yiwu Futian), or a factory with a company name and no store number. The [README workflow and marker table](../README.md#store-spreadsheet-orders) describe the user-facing format; the contracts below explain how to preserve it in code. These describe implemented behavior, not a proposal for general spreadsheet scraping.

### Store identity and purchase dates

- `parseStoreFilename()` in [store-workbook-model.js](../src/store-workbook-model.js) strips familiar Windows duplicate suffixes repeatedly: `12345.xlsx`, `12345 (2).xlsx` and `12345 (5) (Copy).xlsx` identify the same market store. Company-name files and their copy suffixes identify the same factory. Numeric stems produce `market:<number>`; factory keys use the lowercased remaining stem. Renaming the displayed store does not change this key.
- A spreadsheet snapshot has `sourceType: 'spreadsheet'`, `store: { key, name, number, kind }`, and `spreadsheet: { filename, sheetName, importedAt, total, rows }`. `kind` is `market` or `factory`; only market stores have a numeric `number`. `sellerName` is the displayed name and `sellerMemberLogin` is `store:<key>` for preparation identity. `sourceUrl` is empty. Never generate a 1688 link or schedule a 1688 refresh for these orders.
- `repository.importStoreOrder()` always creates a new internal order ID and atomically saves the validated order, original pictures and capacity annotations. Reimporting a filename never updates or merges an existing order. Several orders can share one store key; source groups remain scoped to their order.
- Purchase date must be explicitly confirmed. [store-order.js](../src/store-order.js) stores that calendar date at noon `+08:00`; `importedAt` records import time separately. Orders and Products sort by purchase timestamp, newest first, and successful import updates the open workspace immediately. Source-row order remains intact inside each purchase.
- `repository.renameStore()` changes spreadsheet display names across the same store key in the account; 1688 seller names are not editable. **View all orders from this store** also works for 1688 sellers using their known member login. Never join stores by a matching display name alone.
- Optional `OrderRecord.storeWechat` and `storeWechatUpdatedAt` sit outside `snapshot`. `setStoreWechat()` shares the contact across same-account orders with the same known source/store identity; unknown sellers remain isolated. New imports inherit known contacts. Saving blank clears the ID; newer edits and clears survive source refresh and full/scoped restore. The copy icon never contacts WeChat.

### Marker parsing and validation

[store-workbook-worker.js](../src/store-workbook-worker.js) runs the bundled SheetJS reader for XLSX and genuine BIFF8 XLS. [store-workbook-reader.js](../src/store-workbook-reader.js) extracts raster images with anchors and merges. The model validates the selected sheet; formulas and macros never execute. Formula cells need saved cached results without Excel errors. Ask the user to recalculate/save the workbook when those results are missing.

The only canonical markers are `pic`, `desc`, `boxes`, `perbox`, `qty`, `price`, `amount`, `group`, `var`, `kg`, `cbm`, `cbmx`, `cbmy`, `cbmz` and `total`. Marker matching trims whitespace and ignores case. Old pinyin names and accidental alternatives such as `variants` or `totalp` are not aliases. Keep `STORE_IMPORT_MARKERS` and [store-spreadsheet-guide.js](../src/store-spreadsheet-guide.js) aligned with the README and template.

- Use one marker row above the seller headers; column order is arbitrary. Only `desc` can repeat in that row. Unmarked columns are ignored even if their headers look meaningful. Blank `group` cells skip rows, including rows containing other data. Equal group values collect rows regardless of adjacency; they never become assigned CE codes.
- `pic`, `group`, `boxes` and `price` are required, plus at least one of `perbox` or `qty`. For included source rows, cartons and piece counts are positive whole numbers. Derive `qty = boxes × perbox`, or derive `perbox = qty ÷ boxes` only when it is an exact whole number. If both are present, verify their equality. Spreadsheet imports require exact carton quantities; 1688 remainder handling is a separate review path.
- Validate optional `amount` against `price × qty`, and validate the independent whole-order `total` against all included rows. Exactly two `total` cells must surround one populated control cell in the same row or column. Extra/unpaired controls reject. Money uses the exact-decimal/cent helpers in [money.js](../src/money.js), not floating-point tolerance or a guessed difference.
- `parseStoreNumber()` accepts a single number with ordinary currency/unit text (`6元`, `8RMB`, `20.5 K.G.`, `0.14 CBM`). Workbook decimals use a point; commas are valid thousands separators only. Arithmetic expressions, dimensions crammed into one numeric cell, multiple numbers and ambiguous values reject. Inline workspace measurement editors separately accept decimal commas; do not apply that convention to workbook parsing.
- Join marked `desc` fragments with a centered dot and surrounding spaces (`A · B`) and preserve source text. Nearby seller headers on those marked columns identify roles such as `ITEM NO`/`货号`/`型号`, `Color`/`颜色`, `Size`/`尺寸`, and `Material`/`材质`. Retain seller article numbers as strings, including leading zeros. These properties feed existing naming, color, size, measurement and material recognition; unrelated unmarked columns never become descriptions.
- [spreadsheet-properties.js](../src/spreadsheet-properties.js) supplies read-only recognition properties from all retained `desc` fragments for items with spreadsheet `sourceGroup` identity, including older imports whose `skuProperties` only retained header-identified fields. Known property values and article numbers are deduplicated before using the shared size/color matchers. Material recognition already reads the combined description. No source snapshot or saved code is rewritten. Comparable measurements use normal size ranking and configured aliases; unitless measurements retain their units as unknown and incompatible dimensions require review. Pending size reanalysis compares the authoritative spreadsheet source group rather than its differing product titles; manually merged source groups stay excluded. Rebuilding existing assigned codes still requires the normal reset review.
- Packing rows retain each spreadsheet product's combined source title directly below its code; spreadsheet group headers omit the first product's title. Attributes, material and cost share the next wrapping row. `packing-workspace.js` passes source type and separate title/attribute hosts through the renderer and its language refresh; 1688 keeps its group-title display. Shared barcodes retain every distinct source description. `packing-descriptions.spec.mjs` covers market/factory rows, compact geometry, multiline variant notes, narrow wrapping, language changes, shared barcodes and unchanged source snapshots.
- Missing/unreadable pictures block import. A readable photo is reused on every included row covered by its anchor or explicitly merged `pic` cell, even when those rows belong to different groups. A photo covering multiple included rows requires shared-photo review, with every affected group and cell shown. Blank groups are skipped, anchor endpoints with zero offsets stay exclusive, and group membership never extends a photo to uncovered rows. Multiple linked pictures per product are retained; identical originals use the existing content-addressed asset once. Never silently assign a nearby unrelated image to fill a missing photo.

[store-import-dialog.js](../src/store-import-dialog.js) presents source cells, values, photos and colored arithmetic comparisons in compact review cards. **Check all** only checks eligible warning acknowledgments. It cannot bypass blocking errors, variant quantity allocations, confirmed purchase date or final photo/total confirmation. The dialog terminates its parsing worker on close and locks dismissal during the atomic save. Instructions remain in the translated Setup / Markers / Checks sidebar, also available from Settings Data. The template download is a compact labelled icon beside Purchase date, with the same control order on narrow layouts.

### Variants, cartons and additional charges

`group` defines a product group; `var` declares explicit variant/size endings. Separate rows such as `a`, `b`, `c` remain separate source rows. One row marked `abcd` represents combined totals for A/B/C/D, never four copies of its quantities or price amount. Review requires a positive quantity for every declared variant, summing to the existing source quantity. Per-variant rounded amounts must also sum to the original row amount.

`abs`, `abm`, `abl` mean A/B in sizes S/M/L. Distinct sized assortments can coexist in one group; repeated or ambiguous nested assortments reject. Do not divide totals equally or infer the split from picture count. Each failed order retains one `lastFailure` through retries, including a successful retry. Failed detail reads capture bounded financial evidence: up to 30 total fields, payable/discount summary text, product counts and aggregate amounts, and up to 25 price/quantity/discount samples with explicit omitted counts. Reports omit filters, page HTML, product descriptions/images and session data. Evidence stays local; no automatic upload occurs. Progress responses omit saved evidence; report export reads the full job directly from shared IndexedDB.

When a product discount amount cannot be parsed, diagnostics retain its exact amount text, capped at 160 characters, and source row number. An exact `包邮` badge is nonmonetary and ignored; other malformed monetary entries still fail. Failed reads also retain bounded raw financial text beside sampled values, including summary/amount/price text, to diagnose direction or duplicate-presentation problems. No tolerance is applied to unexplained cent differences; unsigned price changes require one exact reconciliation of the complete financial evidence.

Reports do not restart jobs and are not database backups. Use a backup alongside a report when analyzing imported product data. A paused scan retains discovery; completed-with-errors retry revisits only failed orders. Unknown total labels fail promptly without spending the hydration timeout, and the import continues with other orders. The 667-order synthetic regression covers 67 pages, scan interruption, independent controller recovery, partial failure and retry without rereading successful details. Real site layouts and amount presentation require separate acceptance; synthetic fixtures are not the user's database.

Removing an order also removes its history and preparation, and releases its code assignments; shared images can remain cached. Unfetched pictures require a connection. The active light/dark mode, interface language, purchase-month filter, Headers, copy-column choices, packing-export options and Activity read fingerprints belong to browser preferences and are not included in backups. Floating import-panel minimization is sessionStorage presentation state, separate from durable jobs. Theme palettes, badge colors and tag/color definitions are packing preferences and do enter backups. One buyer account per library is supported.

## Browser verification

Store-order headings are nonselectable table rows; product selection, continuous row numbers and copying use source entry keys only. The packing row's source facts are restricted to its open scope: normalized exact unit prices and a BigInt quantity sum, without discount adjustment. Copy feedback retains the button's dimensions and places progress/cancellation outside the toolbar flow. Hover helpers close immediately after pointer exit; only keyboard-origin focus can keep an accessible description open.

The products toolbar uses responsive grid tracks with dedicated space for changing selection and packing-scope text. Selection must not shift the table between pointer clicks; browser regressions exercise selection, deselection and genuine double-click activation in all three languages at desktop and narrow widths. Reset tests hold a real preparation write transaction and then wait for the fieldset's native disabled property to clear before checking the action's final disabled state or exporting the saved backup. Playwright's enabled matcher does not observe disabled fieldsets, so it cannot serve as this persistence barrier.

Import progress uses durable job checkpoints (`detailStage`, `detailStartedAt`, `detailAttempts`, `currentRows`, `latestResult`, per-order `savedRows`). The bar counts scanned list pages during discovery, then processed orders (saved plus failed) during details. Saved, attention and pending counts remain separate. Row counts advance only after snapshot persistence; legacy done entries are counted from saved snapshots once on resume. Missing legacy counts stay explicitly unknown. Retry never double-counts rows. Pause/restart clears active-reader fields while retaining results.

`import-progress.js` shares the read-only presentation between Activity and the detail-page control. `READER_STATUS` verifies the owned tab, top frame, job marker and current order; it bypasses the mutation lock so a pending detail read cannot block its own progress display. Polling does not pump or mutate jobs. Reader polls every 1.5 seconds and releases timers on disposal; Activity polls every two seconds and updates existing progress nodes without recreating action buttons or reading saved orders. Elapsed time is labelled as time on the current order, not evidence of new data. Only saved/failed checkpoints change the processed count. No ETA is inferred.

`activity-state.js` keeps read fingerprints by job ID in localStorage, bounded to 500 jobs. New jobs, state transitions and changed failure counts/errors become unread; elapsed-time and ordinary row-count ticks do not. Opening Activity marks visible jobs read while running imports retain their ongoing indicator. Settings controls independent per-mode colors for ongoing/new activity, applied only to the compact count badge rather than the whole neutral button. `floating-panel.js` shares minimize/restore controls for list/detail import panels: hiding the body preserves its progress summary and underlying import work. Minimized state is retained only for the page's browser-tab session. Neither read state nor minimizing starts, pauses, dismisses or deletes a job.

Activity **Dismiss** and **Dismiss all** directly set dismissal on nonrunning jobs without another confirmation. Running jobs have no dismiss action. **Show dismissed** reveals that history; dismissal never deletes saved orders or changes job results.
