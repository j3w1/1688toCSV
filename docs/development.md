# Development

Use Windows-native Node.js 24 and the workflow in [AGENTS.md](../AGENTS.md). Edit sources, rebuild explicitly, then test the generated **dist** extension. There is no watch mode.

| Command                               | Purpose                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------ |
| `npm run verify`                      | Source/docs checks, unit tests, production rebuild and isolated Chromium tests |
| `npm run build` / `npm run build:dev` | Build the complete extension once into dist                                    |
| `npm run test:browser`                | Test the current build with synthetic pages in a temporary profile             |
| `npm run test:excel`                  | Windows Excel integration check in an unsaved workbook; restores the clipboard |
| `npm run preview`                     | Synthetic preview; `/library.html` opens the workspace                         |
| `npm run screenshots`                 | Regenerate workspace and label-editor images using synthetic data              |
| `npm run check:docs`                  | Validate local links, screenshots and documented commands                      |

For UI changes, regenerate screenshots and check documentation after final verification. Keep the main README practical; record only necessary developer constraints here. Do not commit private orders, exports, captures, profiles or credentials.

[CI](../.github/workflows/ci.yml) routes docs-only changes to documentation checks, code to full verification, and mixed changes to both. Its stable `required` check rejects failures, cancellations and unexpected skips. Desktop Excel is tested locally, not in hosted Linux CI.

## Boundaries

Page adapters extract and validate source data. Monetary calculations use exact cents. IndexedDB stores snapshots, history, notes, import checkpoints and separate packing data. The import controller owns bounded retries and tab navigation; the library owns filtering and clipboard presentation. Add layout support in adapters and synthetic fixtures, keeping selectors out of the library UI.

Full order and product-entry IDs remain strings. Only complete snapshots that reconcile with displayed totals replace saved data. Changed data creates a retained version; notes and tags remain separate. Failed reads preserve the last good snapshot. Purchase dates describe the source order, not the time it was imported; unknown dates remain unknown until a successful refresh supplies them. Once established, purchase time stays fixed across list and detail reads.

Imports use one visible, marked reader tab. Preserve tabs navigated away from the importer and never resume saved bulk queues automatically. **Open Workspace** opens the library; **Open Workspace here** refuses to replace a tab used by a running import. The embedded browser can reject new tabs. Dismissing an import notice hides it without deleting its job or order records.

Render at most 50 expanded order cards and 100 product rows per page. Month headings stay available independently of card pagination. Filtering and selection still include all matching records. Purchase-date ranges are inclusive; an empty matching scope must never fall back to all saved orders. Confirm multi-order import/refresh before starting; copy actions have no confirmation warning. Column and numbered image-batch choosers select output rather than confirm risk. `IMPORT_PROGRESS` updates jobs only; `LIBRARY_CHANGED` reloads saved records. Progress alone must not rescan or rebuild the product library.

The **1688 Packing workspace** switches between full **Orders** and **Prepare packing list** views. The launch action shows the exact selected product/order scope beside the packing month. **Ctrl+A** in the product table selects all filtered rows across orders and pages. No-selection launch reopens active products already assigned to that packing month across the library; it never infers preparation scope from purchase dates. Groups have an editable product-code heading, Spanish name below and a distinct selection background. The order chooser retains full identifiers; **Open selected order** requires exactly one chosen order, reuses one destination tab and guards overlapping clicks. **Copy order number** preserves the full string. Shared SVG icons use accessible labels; icon-only controls need a hover/focus hint. Nested hints belong to the nearest field and dismiss on editing or Escape without closing another overlay. Restore icons after copy feedback changes button text.

Settings uses keyboard-operable Labels, Product names, Size codes and Data tabs. Naming rules search all four fields; size rules search aliases and endings. Both editors render 12 rules per page and retain the shared draft across searches and page changes. `size-vocabulary-settings.js` updates the draft without saving and reveals invalid or duplicate aliases even on another page. Saving preferences validates rules and representative barcode/carton renders, then reloads suggestions and preparation caches. Preference broadcasts refresh source metadata; ordinary preparation broadcasts only reload preparation data. Data contains backup/restore and full-library refresh.

## Copying and calculations

Orders-view copying includes selected product rows, or all filtered rows across pagination when none are selected. Headers default off; the Headers choice and packing-column choices persist separately in browser preferences. Order dividers are presentation only. Product images use original CDN sources; individual image copying preserves their pixels, while bulk images use a compact display size for standard Excel rows. They paste as separate floating pictures, not native in-cell images.

The packing view's top copy toolbar freezes only selected groups/variants within the displayed packing orders and the original entry-ID scope. It captures those rows before waiting for autosave, then resolves their latest saved values; later selection/filter changes cannot replace the requested rows. It is disabled with no selected product rows. **Ctrl+A** selects the displayed packing scope across pages. Copy actions flush valid pending edits and follow saved group/variant order. Barcode output deduplicates source rows sharing a confirmed variant; carton output emits one mark per product group. Changing the packing-order display filter does not expand the original product selection.

Price is the displayed base unit price, which can already include wholesale reductions. Discount is the displayed row reduction plus its share of any whole-order adjustment not already included. Allocation is proportional after item discounts, with deterministic cent rounding; price increases produce negative allocations. Shipping remains separate. Optional `totals.customizationService` and `totals.redPacketDiscount` retain `定制服务` and `红包` separately. Payable must equal goods net plus shipping plus customization service minus the red-packet reduction. These optional amounts are nonnegative; the red-packet field requires an explicit reduction sign. Neither changes product discounts. Absence remains compatible with old snapshots/backups. Unknown financial fields, unsupported installments and inconsistent totals fail validation. Legacy CSV exports item discounts only.

An explicit `批发优惠` can already be reflected in displayed unit prices. Accept a gap between the original goods total and summed row values only when it equals the whole explicit wholesale discount, customization service already included in the original total, or their sum, with exactly one supported interpretation; retain it as optional `totals.priceIncludedDiscount`. `goodsGross` retains the original footer value. Optional `totals.grossIncludedCustomization` records only zero or the whole explicit customization charge already in that original total. Database save/restore enforce original gross = row gross + price-included discount + gross-included customization; goods net excludes customization, and payable adds it exactly once. A positive `商品改价` can already be included in row discounts: consider only zero or the whole adjustment, recording the latter as optional `totals.rowIncludedAdjustment`. Allocate only the remainder. Reject partial or ambiguous interpretations.

An explicit `店铺优惠` or `活动优惠` can already be included in row discounts or appear only in the footer. Its order-only remainder equals displayed discount breakdown minus price-included wholesale discount plus row-included adjustment minus summed row discounts. Require exactly one supported interpretation with a remainder between zero and the sum of explicit shop and promotion reductions; store a positive remainder in optional `totals.orderDiscount`. Goods net equals summed row values minus source discounts, remaining allocated adjustment and order-only discount. Database save/restore enforce these equations, including that an included adjustment cannot exceed summed row discounts. Validate the discount summary against the original displayed breakdown first. An explicit signed `元宝` reduction can contribute to the displayed discount breakdown when row discounts and supported order-only coupons reconcile exactly; it is not automatically treated as a second payment deduction. Never use a payable discrepancy to invent a discount. Older snapshots omit the new fields.

The Orders search matches seller name/member login and full or partial order IDs, combining with purchase months/date range. The purchase-month filter defaults to the local current month only when no preference exists, then persists across reloads; an explicitly empty selection means all months. Month buttons toggle individually; Shift adds the inclusive month range. Collapsing a month changes navigation only, not filter or copy scope. Initially only the current month is expanded. Search resets bounded pagination and selections; zero results stay empty. Contextual refresh uses selected orders or the current matching scope, including product filters; confirmations freeze exact IDs. Full-library refresh remains in Settings. Running list progress distinguishes earlier failed reads from a job-level blocker; detailed failures stay in Activity and reports.

`order-summary.js` sums complete matching orders once per account/order ID using cents. The summary sits below the products table. Product filters choose which orders contribute; they never allocate shipping or order-only discounts to the visible product subset. The scope label states this explicitly. Summaries show original total, shipping, seller changes, effective product discounts, order-only discounts, red packets, additional customization service and total payable. Effective product discounts remove seller changes already represented in source discounts and add discounts already reflected in unit prices. Customization already included in original gross is not added again. Do not label payable as paid, infer missing amounts as zero, or invent a PLUS/shop breakdown absent from saved snapshots. Missing, inconsistent and unspecified-fee records remain visible as warnings.

The exact `外币支付手续费` placeholder `（≈）` or `(≈)` is preserved as optional `foreignCurrencyFeeUnspecified: true`, with an English amount-not-shown notice. It is not a numeric zero or an inferred exchange fee. An amount-bearing, empty or different fee display remains unsupported, and all CNY totals must independently reconcile. Older snapshots omit the optional fields.

## Packing data and labels

Preparation is authored separately from source snapshots. Grouping uses structured titles and SKU attributes when available; legacy descriptions remain a fallback. A group has one base code, with variants linked to source entry IDs. Non-size attributes distinguish variants; size is separate. Suggestions never aggregate or alter source prices, quantities or discounts. Refresh preserves preparation edits; removed entries stay recorded but are excluded from current label output, and new entries need preparation review.

The packing view shows product photos with original-image zoom, carton previews per group and barcode previews per variant. Chinese categories, original product names, grouping tools and code options stay visible; preparation has no collapsible sections. Compact controls preserve keyboard access and larger coarse-pointer targets. Unfinished previews wrap validation text without reserving full label-image space. **Share one barcode** combines selected variants without combining their financial rows; **Give rows separate barcodes** restores individual variants; **Move to new product** gives selected variants a separate group. Grouping changes preview affected products and codes before saving. Groups cannot merge across orders or packing months, and partly selected groups must be selected in full before membership changes. Hover/focus hints use Escape dismissal and a Chrome 120 positioned-popover fallback. Source size is reference data for initial suggestions; only its code ending enters the barcode payload.

The packing header shares space with save/history actions and the top copy toolbar. Order headers separate seller identity, full order number, shared naming and restore actions from the product groups below. The order chooser includes seller, Chinese categories and Spanish names. Each group's Spanish name is edited below its product-code heading without a duplicate field. Paired order-level naming controls apply only changed Spanish/Chinese values. Product fields and original names sit beside the carton preview; editable variant notes wrap. Joined base/variant/size controls show the composed code while preserving separate validated values and keyboard order.

`excel-image.js` renders a white table image with eight centered Chinese headers: 序号, 图片, 产品描述, 唛头货号, 条码货号, 中文品类, 单价（元）, 数量. Spanish names and discounts remain available in other copy formats but are omitted from this image. The warm header, bold quantities and structured title/attribute formatting are presentation only. Manually reordered groups or products mark their exported base-code text blue; barcode endings retain their normal color. `excel-image-copy.js` freezes selection, offers numbered batches when needed and writes a single PNG without a confirmation warning. The packing view flushes valid autosaves first. Image headers are always included regardless of the text/table Headers preference. The renderer never allocates codes. Images use 2× resolution and 192 DPI metadata; batches stay within 16 million pixels and an 8192px edge. Long text wraps without truncation. Photo failures stop copying, cancellation preserves the clipboard, and canvases/image resources are released. Base codes appear once per group in each batch.

The browser clipboard can normalize PNG resolution metadata. Excel's default PNG paste uses its native picture size; the table image is resizable rather than a fixed-size print label. Native acceptance checks selected-row pixels, exactly one embedded picture and unchanged destination cells. Barcode/carton labels keep their separate physical-size copy path.

`photo-viewer.js` shares original-image viewing between table thumbnails and preparation: pointer-anchored wheel zoom, captured drag-to-pan, double-click zoom, Fit/100%, arrow-key panning and fullscreen. Percentages use natural image pixels. Resize/close releases observers and drag state; image transforms stay bounded. Display-only order status mappings retain the original status in storage, filter values and tooltips; unknown statuses remain untranslated. Purchase dates use semantic `time` elements and compact visual chips.

`row-selection.js` shares click, Shift-range and Ctrl/Meta-toggle selection across orders, product rows and preparation. Clicking a selected row again deselects it; the second click event of a double-click must not undo the first selection. Order cards open details on double-click or Enter. Native controls and nested selection scopes are excluded from parent selection. Arrow/Home/End navigation uses visible rows; Shift ranges and Select all use the full filtered scope across pagination. Filter changes reset anchors. Roving focus and selection attributes remain explicit; preference checkboxes retain native keyboard behavior. Selection instructions use a hover/focus hint. Preparation retains selected IDs independently of edits, and detaches DOM bindings on rerender/close. Selection must never write preparation data or trigger autosave.

Keep the interface free of blue tones: use warm charcoal/cream surfaces, amber and coral accents, and sage success states. Apply the same palette to focus rings, date selections and label-editor controls. Printed labels remain black and white; blue is reserved for the requested reordered-code indicator in exported Excel table images.

Preparation barcode editors receive explicit `baseCode`, `variantSuffix`, `sizeSuffix` and mapping state. Separate fields overlay the fixed barcode band; their updates persist exact suffix values through the existing transactional preparation save. The base is read-only there and edited on the carton/product code. The composed payload still passes the local encoder, size/overflow and duplicate-code validation before saving or copying. This avoids guessing the variant/size boundary from one freeform payload. Carton text fits actual glyph bounds, with shared editor bounds and blank writing lines retained at the configured physical size.

Preparation autosaves after 800 ms idle and flushes before returning to Orders or label output. The selected source-entry IDs are frozen before `planSelectedPreparations()`; it prepares exactly that scope across orders. Changing packing month moves only selected entries. A partially selected group splits into a new group while unselected entries keep their group, month and codes. `previewPreparations()` produces the old/new-code review without issuing reservations; `savePreparations()` allocates and saves all participating orders atomically after confirmation. Stale revisions or ownership conflicts reject the whole save. Cancel performs no writes.

`preparation-save.js` acknowledges submitted values in place while preserving newer typing and field references. Successful writes update the affected membership cache. Invalid/conflicting edits remain in the packing view with inline status. **Resolve** queries reservation ownership and shows the original owner, photos, current code and whether the conflicting code is active or historical. The user may show the owning product, use a new available code, keep the saved version or continue editing. **Reload saved version** discards only the failed order draft without a confirmation; it does not free reservations or affect other drafts. Cross-tab conflicts never overwrite newer revisions.

`packing-reorder.js` supports dragging and keyboard movement. Groups move only within their source order; variants move only within their product group. Positions and `manualReordered` metadata are authored preparation data, independent of source observation order. Reordering does not regenerate codes or change source prices/quantities. Output follows the saved group and variant order. **Reset order and codes** restores that order's default grouping, source order, codes and endings, preserving current names and notes where stable identities still match. **Restore previous packing** replaces the order with the checkpoint before its latest month move, including names, grouping and codes; it also keeps the displaced state as the next previous checkpoint. Both actions show affected photos and code changes, validate current ownership and retain every issued reservation.

`preparation-history.js` retains at most 50 edits or 8 MiB, coalescing typing until focus leaves a field. Undo/Redo cover pending edits only; autosave clears committed history without releasing issued codes. Grouping and Undo wait for active writes. `preparation-media.js` observes visible tiles, renders one label and loads up to two photos at a time, and invalidates changed label content only. Its label cache is capped at 16 MiB; reduced photos at 40 entries/4 MiB. Combined photo galleries show four additional thumbnails per page without a disclosure. Release tile URLs on exit/reset. Form photos use reduced bitmaps from the shared image loader; zoom displays the original source.

Missing source seller identity is explicit: `sellerUnavailable: true`, `sellerName: 'Seller unavailable'`, and no member login. Import still requires complete rows and reconciled totals. New preparation starts with an empty `sellerId`; the user must enter the seller member login before allocation. Placeholder identities cannot allocate codes. This authored identity survives source refresh and backup independently of the source flag; missing sellers never share a synthetic allocation group.

Initialize Packing month once per workspace opening from the local calendar year/month. Rendering, refresh and switching views preserve an explicit choice. Existing group months change only through the selected-product planning and confirmation path; purchase-month filters never renumber products. New preparation reads its chosen packing month independently of source purchase dates. Overlays support backdrop dismissal with native `closedby` and a pointer-boundary fallback. Closing a confirmation cancels work. Label dismissal waits for a pending valid blur-save; invalid edits keep their explanation visible.

The chosen packing month controls `CEYYMMGGII`: `GG` is a monthly seller group and `II` the product number within it, both `01`–`99`. Seller identity prefers the source member login and falls back to the seller name. Allocation continues across that seller's orders, opens another group after item 99, and fails when all monthly groups are exhausted. Allocation and preparation save together in one transaction. Issued base codes and full barcode strings remain reserved after edits or order deletion; conflicting manual codes are rejected. Revision checks reject stale edits from another tab.

Barcode text concatenates base code, variant suffix and size suffix. Variant suffixes use uppercase letters; size suffixes allow uppercase letters and digits. `size-vocabulary.js` extracts size evidence from SKU attributes and legacy description lines, never product titles or article/model IDs. Editable literal aliases separated by `|` map to 1–12 uppercase letters/numbers; duplicate aliases are rejected. Explicit named labels remain recognizable. Compatible scalar or vector measurements normalize length, capacity and mass units; nominal 寸 stays a separate unit. Materials, colors, sets and packaging remain non-size variant information.

Two distinct comparable measurements suggest S/L, three S/M/L, and five XS/S/M/L/XL. Equal measurements may share endings only when other attributes distinguish their variants. Crossing dimensions, incompatible units, mixed or missing evidence, ranges, composite sets and other assortment counts remain unresolved. `resolvePendingSizeMappings()` fills only unresolved, empty endings and rejects duplicate resulting barcode endings; manual mappings, intentional clears and issued codes are preserved. **Settings → Size codes** edits local aliases without adding a translation service or silently remapping prepared labels.

`product-vocabulary.js` contains generic local title rules for uppercase Spanish names and Chinese categories. Literal alternatives, exclusions and rule priority distinguish product types; user rules override bundled matches. Unknown products and conflicting fields stay blank. For example, a reed diffuser maps to DIFUSOR / 香薰, not the candle category. No translation or AI service is called. **Settings → Product names** edits the rules; saving them updates eligible suggestions without a separate Apply step.

Imports store derived naming suggestions beside source snapshots. Restore and `refreshNamingSuggestions()` backfill existing records without allocating codes. Group `naming` metadata tracks automatic and manual fields independently. Explicit edits, including clearing a name, remain authored; nonempty legacy names are also preserved. Automatic changes increment preparation revisions so concurrent edits cannot overwrite them. Vocabulary seeding must not outrank a user's saved settings during restore, and deleted rules must not reappear on reload. Suggestions never change financial rows, membership or code reservations.

Labels render locally as PNGs: the default barcode is 40 × 20 mm and the carton mark is 148.5 × 105 mm, both at 300 DPI. Code 128 bars use integer pixel widths and quiet zones; text that cannot fit or a barcode that is too dense reports an error. The black code band follows the fitted text with small horizontal padding. Carton marks emphasize CE, the base code and Chinese category while keeping the blank quantity, KG and CBM fields compact. Shared field bounds align the constrained editor with the rendered text. It commits on Enter or blur and restores saved text on Escape. A single label copies PNG plus HTML with physical dimensions; batches use one image per HTML table row. Visible preparation previews render on demand; copy and editor output retain full print resolution. Rendering uses a bounded cache and limited concurrency. Printer/scanner and spreadsheet acceptance remain separate from rendering tests.

Future workbook automation should consume validated snapshots plus preparation membership, codes and settings. Add carton measurements, loading inputs and validated freight/discount allocation before template-based XLSX generation. Reuse grouping, allocation and label rendering; do not infer identity from row position or copy formulas from historical workbooks. Direct workbook writing is not implemented in this release.

## Backups

The packing toolbar derives its backup filename and `packingScope.months` from the currently scoped groups, including after restoring an earlier packing. The original launch month is not reused after a restore changes those groups.

The on-page **Save import report** action requests a fresh full job from the worker using `IMPORT_REPORT`; it validates the originating list tab/frame and reads without acquiring the import mutation lock or pumping the queue. It uses the same report formatter as Activity, with page Blob URLs released after the download request or toolbar disposal.

Version 2 backups include orders, history, notes, cached pictures, preparations, allocation counters, issued-code reservations and packing preferences, including naming provenance, product/size vocabularies and logo. Preparation includes authored order, per-group months and default/previous checkpoints. Import jobs are not restored. Version 1 backups remain accepted. Restore validates the whole file and commits atomically, preserves existing notes, merges newer observations and preparation edits, and rejects conflicting code ownership or equally dated conflicting edits. Older backups cannot lower allocation counters or free issued codes. Derived naming caches can be rebuilt; manual fields remain protected. Full backup/restore lives under **Settings → Data**. **Back up packing** limits source orders to the open packing, but retains each included order's other rows and the code registry required for safe restore. Independent libraries do not coordinate numbering.

Activity can export an `1688-import-report` JSON snapshot with extension version, discovery/save/failure counts, scanned pages and every queued order's ID, canonical detail URL, state, expected row count and error. Each failed order retains one `lastFailure` through retries, including a successful retry. Failed detail reads capture bounded financial evidence: up to 30 total fields, payable/discount summary text, product counts and aggregate amounts, and up to 25 price/quantity/discount samples with explicit omitted counts. Reports omit filters, page HTML, product descriptions/images and session data. Evidence stays local; no automatic upload occurs. Progress responses omit saved evidence; report export reads the full job directly from shared IndexedDB.

When a product discount amount cannot be parsed, diagnostics retain its exact amount text, capped at 160 characters, and source row number. An exact `包邮` badge is nonmonetary and ignored; other malformed monetary entries still fail. Failed reads also retain bounded raw financial text beside sampled values, including summary/amount/price text, to diagnose direction or duplicate-presentation problems. No tolerance is applied to unexplained cent differences; unsigned price changes still require row-level evidence.

Reports do not restart jobs and are not database backups. Use a backup alongside a report when analyzing imported product data. A paused scan retains discovery; completed-with-errors retry revisits only failed orders. Unknown total labels fail promptly without spending the hydration timeout, and the import continues with other orders. The 667-order synthetic regression covers 67 pages, scan interruption, independent controller recovery, partial failure and retry without rereading successful details. Real site layouts and amount presentation require separate acceptance; synthetic fixtures are not the user's database.

Removing an order also removes its history and preparation, but keeps issued codes reserved; shared images can remain cached. Unfetched pictures require a connection. Theme, purchase-month filter, Headers and copy-column choices belong to the browser and are not included in the packing backup. One buyer account per library is supported.

## Browser verification

Store-order headings are nonselectable table rows; product selection, pagination counts and copying use source entry keys only. The packing row's source facts are restricted to its open scope: normalized exact unit prices and a BigInt quantity sum, without discount adjustment. Copy feedback retains the button's dimensions and places progress/cancellation outside the toolbar flow. Hover helpers close immediately after pointer exit; only keyboard-origin focus can keep an accessible description open.

Import progress uses durable job checkpoints (`detailStage`, `detailStartedAt`, `detailAttempts`, `currentRows`, `latestResult`, per-order `savedRows`). The bar counts scanned list pages during discovery, then processed orders (saved plus failed) during details. Saved, attention and pending counts remain separate. Row counts advance only after snapshot persistence; legacy done entries are counted from saved snapshots once on resume. Missing legacy counts stay explicitly unknown. Retry never double-counts rows. Pause/restart clears active-reader fields while retaining results.

`import-progress.js` shares the read-only presentation between Activity and the detail-page control. `READER_STATUS` verifies the owned tab, top frame, job marker and current order; it bypasses the mutation lock so a pending detail read cannot block its own progress display. Polling does not pump or mutate jobs. Reader polls every 1.5 seconds and releases timers on disposal; Activity polls every two seconds and updates existing progress nodes without recreating action buttons or reading saved orders. Elapsed time is labelled as time on the current order, not evidence of new data. Only saved/failed checkpoints change the processed count. No ETA is inferred.

Packaged tests cover selection, navigation, extraction, persistence, spreadsheet copying, delayed rendering, failed-job retry, preparation edits and label output. Large-library cases cover pagination and progress without full-library reads. The isolated test copy substitutes reserved `.test` domains and serves synthetic pages locally. Test-only permissions and hosts never enter the production build. Remote requests are blocked. Run clipboard browser suites and the desktop Excel check sequentially so they cannot overwrite each other's clipboard. Coverage describes the tests; consult the release record for which checks have actually passed.

```powershell
} finally {
  Remove-Item Env:\EXTENSION_TEST_CHANNEL
}
```
