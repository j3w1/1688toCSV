# Development

Use Node.js 24 and the workflow in [AGENTS.md](../AGENTS.md): iterate locally with `npm run try`, and run full verification once at deploy. Edit sources, rebuild explicitly, then test the generated **dist** extension. There is no watch mode.

| Command                               | Purpose                                                                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `npm run try`                         | Unit tests, development build, stage into the installed extension, reload it through CE Dev Browser and confirm library counts |
| `npm run verify`                      | Source/docs checks, unit tests, production rebuild and isolated Chromium tests                                                 |
| `npm run build` / `npm run build:dev` | Build the complete extension once into dist                                                                                    |
| `npm run test:browser`                | Test the current build with synthetic pages in a temporary profile                                                             |
| `npm run test:excel`                  | Windows Excel integration check in an unsaved workbook; restores the clipboard                                                 |
| `npm run preview`                     | Synthetic preview; `/library.html` opens the workspace                                                                         |
| `npm run screenshots`                 | Regenerate workspace and label-editor images using synthetic data                                                              |
| `npm run check:docs`                  | Validate local links, screenshots and documented commands                                                                      |

For UI changes, regenerate screenshots and check documentation after final verification. Keep the main README practical; record only necessary developer constraints here. Do not commit private orders, exports, captures, profiles or credentials.

[CI](../.github/workflows/ci.yml) routes docs-only changes to documentation checks, code to full verification, and mixed changes to both. Its stable `required` check rejects failures, cancellations and unexpected skips. Desktop Excel is tested locally, not in hosted Linux CI.

## Boundaries

The main library sorts both order cards and product groups by canonical purchase timestamp descending, with unknown dates last and source product order retained. Packing arrangement is separate. Successful import-save notifications refresh records and detach stale row bindings; new matching orders reset the relevant pagination without clearing filters or selected product keys.

Page adapters extract and validate source data. Monetary calculations use exact cents. IndexedDB stores snapshots, history, notes, import checkpoints and separate packing data. The import controller owns bounded retries and tab navigation; the library owns filtering and clipboard presentation. Add layout support in adapters and synthetic fixtures, keeping selectors out of the library UI.

Full order and product-entry IDs remain strings. Only complete snapshots that reconcile with displayed totals replace saved data. Changed data creates a retained version; notes and tags remain separate. Failed reads preserve the last good snapshot. Purchase dates describe the source order, not the time it was imported; unknown dates remain unknown until a successful refresh supplies them. Once established, purchase time stays fixed across list and detail reads.

Imports use one marked reader tab created blank in the background (`active: false`, not auto-discardable) and then navigated, so the visible tab never changes; browsers that reject background extension tabs fall back to a visible reader and the job records `visibleReader`. When the reader leaves its order page (sign-in or verification), the job pauses with `attention` naming that tab; the workspace shows one notice whose button is the only path that activates it, and Resume clears it. Preserve tabs navigated away from the importer and never resume saved bulk queues automatically. **Open Workspace** opens the library; **Open Workspace here** refuses to replace a tab used by a running import. The embedded browser can reject new tabs. Dismissing an import notice hides it without deleting its job or order records.

Render at most 50 expanded order cards and 100 product rows per page. Month headings stay available independently of card pagination. Filtering and selection still include all matching records. Purchase-date ranges are inclusive; an empty matching scope must never fall back to all saved orders. Confirm multi-order import/refresh before starting; copy actions have no confirmation warning. Column controls and the persistent image preview select output; only an explicit copy action writes the clipboard. `IMPORT_PROGRESS` updates jobs only; `LIBRARY_CHANGED` reloads saved records. Progress alone must not rescan or rebuild the product library.

The **1688 Packing workspace** switches between full **Orders** and **Prepare packing list** views. The launch action shows the exact selected product/order scope beside the packing month. **Ctrl+A/D** selects/clears the active Orders or Products list across its filtered pages; pointer/focus activity determines the list. In packing it acts on the displayed packing scope across pages. Editable fields, composition and open dialogs retain their own keyboard behavior. No-selection launch reopens active products already assigned to that packing month across the library; it never infers preparation scope from purchase dates. A document-level Escape handler returns from packing even with header focus, after valid pending edits save; open dialogs, copy/arrangement panels and native selects handle dismissal first, and invalid edits remain available. **Open selected order** requires exactly one chosen order, reuses one destination tab and guards overlapping clicks. Small accessible source-order links beside order identities open the specific canonical source URL; links and copy controls remain excluded from parent selection/activation. Store names and full order numbers copy directly through unframed native buttons, with brief anchored feedback that neither selects rows nor changes their size.

Source-row annotations are retained if a scrape removes a row, while the containing order exists.

Dismissal locks the annotation inputs while flushing so late typing cannot be discarded; product source/order navigation accepts only the first pending transition. `source-image-copy.js` freezes source values and starts with batches of up to 20 products. Copy actions in the packing selection toolbar freeze only selected groups/variants within the displayed packing orders and the original entry-ID scope. Copying is disabled with no selected product rows; packing backup remains available for the whole open session. **Ctrl+A** selects the displayed packing scope across pages. Copy actions flush valid pending edits and follow saved group/variant order. Barcode output deduplicates source rows sharing a confirmed variant; carton output emits one mark per product group. Changing the packing-order display filter does not expand the original product selection.

Price is the displayed base unit price, which can already include wholesale reductions. Discount is the displayed row reduction plus its share of any whole-order adjustment not already included. Allocation is proportional after item discounts, with deterministic cent rounding; price increases produce negative allocations. Shipping remains separate. Optional `totals.customizationService` and `totals.redPacketDiscount` retain `定制服务` and `红包` separately. Payable must equal goods net plus shipping plus customization service minus the red-packet reduction. These optional amounts are nonnegative; the red-packet field requires an explicit reduction sign. Neither changes product discounts. Absence remains compatible with old snapshots/backups. Unknown financial fields, unsupported installments and inconsistent totals fail validation. Legacy CSV exports item discounts only.

An explicit `批发优惠` can already be reflected in displayed unit prices. Accept a gap between the original goods total and summed row values only when it equals the whole explicit wholesale discount, customization service already included in the original total, or their sum, with exactly one supported interpretation; retain it as optional `totals.priceIncludedDiscount`. `goodsGross` retains the original footer value. Optional `totals.grossIncludedCustomization` records only zero or the whole explicit customization charge already in that original total. Database save/restore enforce original gross = row gross + price-included discount + gross-included customization; goods net excludes customization, and payable adds it exactly once. A positive `商品改价` can already be included in row discounts: consider only zero or the whole adjustment, recording the latter as optional `totals.rowIncludedAdjustment`. Allocate only the remainder. Reject partial or ambiguous interpretations.

When `商品改价` has no sign, consider its explicit amount in both directions (deduplicating zero) alongside the same supported gross/discount candidates. Accept only one complete interpretation that reconciles product rows, discount breakdown and payable in exact cents; retain its signed `orderAdjustment`. Do not assume an unsigned reduction, infer an amount from a gap, or relax `红包` sign validation. Ambiguous or inconsistent totals still fail without replacing saved data.

An explicit `店铺优惠` or `活动优惠` can already be included in row discounts or appear only in the footer. Its order-only remainder equals displayed discount breakdown minus price-included wholesale discount plus row-included adjustment minus summed row discounts. Require exactly one supported interpretation with a remainder between zero and the sum of explicit shop and promotion reductions; store a positive remainder in optional `totals.orderDiscount`. Goods net equals summed row values minus source discounts, remaining allocated adjustment and order-only discount. Database save/restore enforce these equations, including that an included adjustment cannot exceed summed row discounts. Validate the discount summary against the original displayed breakdown first. An explicit signed `元宝` reduction can contribute to the displayed discount breakdown when row discounts and supported order-only coupons reconcile exactly; it is not automatically treated as a second payment deduction. Never use a payable discrepancy to invent a discount. Older snapshots omit the new fields.

The Orders search matches seller name/member login and full or partial order IDs, combining with purchase months/date range. The purchase-month filter defaults to the local current month only when no preference exists, then persists across reloads; an explicitly empty selection means all months. Month buttons toggle individually; Shift adds the inclusive month range. Collapsing a month changes navigation only, not filter or copy scope. Initially only the current month is expanded. Search resets bounded pagination and selections; zero results stay empty. Contextual refresh uses selected orders or the current matching scope, including product filters; confirmations freeze exact IDs. Full-library refresh remains in Settings. Running list progress distinguishes earlier failed reads from a job-level blocker; detailed failures stay in Activity and reports.

`order-summary.js` sums complete matching orders once per account/order ID using cents. Selection and complete-order summaries sit above the products table. Product filters choose which orders contribute; they never allocate shipping or order-only discounts to the visible product subset. The scope label states this explicitly. Summaries show original total, shipping, seller changes, effective product discounts, order-only discounts, red packets, additional customization service and total payable. Effective product discounts remove seller changes already represented in source discounts and add discounts already reflected in unit prices. Customization already included in original gross is not added again. Do not label payable as paid, infer missing amounts as zero, or invent a PLUS/shop breakdown absent from saved snapshots. Missing, inconsistent and unspecified-fee records remain visible as warnings.

The exact `外币支付手续费` placeholder `（≈）` or `(≈)` is preserved as optional `foreignCurrencyFeeUnspecified: true`, with an English amount-not-shown notice. It is not a numeric zero or an inferred exchange fee. An amount-bearing, empty or different fee display remains unsupported, and all CNY totals must independently reconcile. Older snapshots omit the optional fields.

A partially selected group splits into a new group while unselected entries keep their group, month and codes. `previewPreparations()` produces the old/new-code review without issuing reservations; `savePreparations()` allocates and saves all participating orders atomically after confirmation. Stale revisions or ownership conflicts reject the whole save. Cancel performs no writes.

`preparation-save.js` acknowledges submitted values in place while preserving newer typing and field references. Successful writes update the affected membership cache. Product-code fields preview validation after a short input delay, before blur; stale responses cannot replace the latest result. Inline errors expose `aria-invalid` and an adjacent **Resolve code** action without moving focus. Carton editing lists affected scoped products with photos and explains the shared base code/category. **Resolve** queries reservation ownership and shows the current owner, photos and code, plus a labeled comparison of affected proposed barcode values. Recovery choices stage corrections for review before Apply saves. The user may show the owning product, use an available code, keep the saved version or continue editing. **Reload saved version** discards only the failed order draft without another confirmation. Cross-tab conflicts never overwrite newer revisions.

Visible label previews share the draft's code validation state. Local invalid endings and duplicate barcodes immediately revoke affected preview URLs; changed codes wait for reservation validation. Every participant in a duplicate barcode loses its barcode image while valid carton marks and unrelated saved previews remain. The error tile reuses conflict resolution or field navigation without replacing the button's accessible name. Validation responses and completed renders are checked against the current code/model signature so delayed work cannot restore stale images. A successful save approves only the code values actually submitted.

Groups may persist `sizeMode: 'none'` for seller styles that are not distinct sizes. Applying it reviews the affected products, clears size endings/pending flags only, and retains variant letters and code ownership checks. Source reanalysis, partial moves and checkpoints preserve the override; reset can restore the current setup's default mode. Returning to automatic rechecks blank endings. Authoring a nonempty size ending, inline or in the label editor, clears the override and keeps that authored value without an inference pass. Equal complete measurements never use price to invent a size difference.

`packing-reorder.js` supports dragging and keyboard movement of whole orders, groups within their source order and variants within their product group. `packing-arrangement.js` supplies Store, Group code and Store, then group code through one Arrange panel. Only displayed order/group slots are rearranged; code modes compare scoped groups and preserve hidden group positions. Whole-order arrangement assigns the opened orders to their existing global rank slots, preventing subset operations from colliding with unopened orders. Validated `packingPosition` and `packingManualReordered` metadata persist order placement; group/variant positions retain their own metadata. Arrangement and order dragging await pending saves, apply the complete move and flush its writes before controls resume, avoiding partial per-order Undo during autosave. Reordering does not regenerate codes or change source prices/quantities. All exports follow the saved order; manually moved orders contribute the same blue Excel-code indicator as moved groups/products. **Reset order and codes** restores the current setup's default grouping, source order, codes and endings while preserving matching names and notes. `defaultPackingChanges()` detects actual position, membership, code, ending and manual-ordering differences; reset becomes unavailable once none remain. Its review includes order changes even when the before/after base code is identical. **Restore previous packing** separately restores the checkpoint before the latest month move, including names, and retains the displaced state as the next previous checkpoint. Both validate current ownership; checkpoints retain values but never reserve inactive codes.

**Remove group** and **Remove product** review all affected values before discarding session edits. `preparation-removal.js` restores source-entry values from the preparation captured before this session’s automatic assignment, including saved edits; new entries become unassigned. Shared group fields require a visible comparison for linked remaining entries. Only selected entries leave session scope. Empty scoped orders are excluded from the selector and counts. Session history retains before/after scope as well as preparation values, so Undo/Redo restores membership and data together.

`preparation-history.js` retains at most 50 edits or 8 MiB and coalesces typing until focus leaves a field. Autosave acknowledges history without clearing it. Undo/Redo checks current revisions and assignments, never restores a stale database snapshot, and restores multi-order changes atomically. Removal history also stores session membership. Leaving and reopening preparation starts a new session baseline.

Missing source seller identity is explicit: `sellerUnavailable: true`, `sellerName: 'Seller unavailable'`, and no member login. Import still requires complete rows and reconciled totals. New preparation starts with an empty `sellerId`; the user must enter the seller member login before allocation. Placeholder identities cannot allocate codes. This authored identity survives source refresh and backup independently of the source flag; missing sellers never share a synthetic allocation group.

Initialize Packing month once per workspace opening from the local calendar year/month. Rendering, refresh and switching views preserve an explicit choice. Existing group months change only through the selected-product planning and confirmation path; purchase-month filters never renumber products. New preparation reads its chosen packing month independently of source purchase dates. Overlays support backdrop dismissal with native `closedby` and a pointer-boundary fallback. Closing a confirmation cancels work. Label dismissal waits for a pending valid blur-save; invalid edits keep their explanation visible.

The chosen packing month controls `CEYYMMGGII`: `GG` is a monthly seller group and `II` the product number within it, both `01`–`99`. Seller identity prefers the source member login and falls back to the seller name. Allocation continues across that seller's orders, opens another group after item 99, and fails when all monthly groups are exhausted. Allocation and preparation save together in one transaction. Only current preparations own base codes and full barcode strings. `activePackingState()` rebuilds the assignment index from the final candidate set, retaining seller/month slots but discarding inactive codes and their item counters. Save checks all explicit assignments before allocating blanks, permitting atomic swaps while rejecting simultaneous duplicates. Default/previous checkpoints never reserve codes; restoring them goes through the same current-conflict checks. Revision checks reject stale edits from another tab.

Barcode text concatenates base code, variant suffix and size suffix. Variant suffixes use uppercase letters; size suffixes allow uppercase letters and digits. `size-vocabulary.js` extracts size evidence from SKU attributes and legacy description lines, never product titles or article/model IDs. Editable literal aliases separated by `|` map to 1–12 uppercase letters/numbers; duplicate aliases are rejected. Explicit/custom named labels remain recognizable. Compatible scalar or vector measurements normalize length, capacity and mass units, including mixed units within a vector; nominal 寸 stays a separate unit. Named axes are canonicalized by identity, not seller word order: height, diameter, base diameter and opening diameter remain distinct. A named vector must identify every axis exactly once, and compared vectors must contain the same complete axis set. Partial, duplicate or incompatible axes never fall back to a convenient subset; negative named dimensions remain unresolved rather than losing their sign. Materials, colors, sets and packaging remain non-size variant information.

Two distinct comparable measurements suggest S/L, three S/M/L, four S/M/L/XL and five XS/S/M/L/XL. Every step must be nondecreasing on every dimension and strictly increase on at least one; no area or partial-dimension ranking is inferred. Equal measurements may share endings only when other attributes distinguish their variants. Crossing dimensions, incompatible units, mixed or missing evidence, ranges, composite sets and unsupported assortment counts remain unresolved. `resolvePendingSizeMappings()` can re-extract evidence from the original snapshot, but fills only selected unresolved, empty endings. It rejects incomplete shared-row selections, merged unrelated source products, conflicts with explicit/manual endings and duplicate resulting barcode endings. Manual mappings, intentional clears and issued reservations are preserved. **Settings → Size codes** edits local aliases without a translation service or silently remapping prepared labels.

`suggestPriceSizeMappings()` is review-only. Exactly two unresolved variants may receive an S/L proposal only when they have unknown nonnumeric textual sizes, matching title/article/non-size attributes and one positive exact unit price per variant, with distinct prices. Measurement/numeric evidence, differing color/material, explicit/manual endings, missing/inconsistent prices or duplicate resulting endings suppress it. The action is available only when all source entries for both variants are in the open scope. **Review size suggestions** shows photos, source order, exact unit prices and current/proposed barcodes; only explicit confirmation writes the two proposed size endings through normal validation. Price never silently fills a measurement gap.

`product-vocabulary.js` contains generic local title rules for uppercase Spanish names and Chinese categories. Literal alternatives, exclusions and rule priority distinguish product types; user rules override bundled matches. Unknown products and conflicting fields stay blank. For example, a reed diffuser maps to DIFUSOR / 香薰, not the candle category. No translation or AI service is called. **Settings → Product names** edits the rules; saving them updates eligible suggestions without a separate Apply step.

Imports store derived naming suggestions beside source snapshots. Restore and `refreshNamingSuggestions()` backfill existing records without allocating codes. Group `naming` metadata tracks automatic and manual fields independently. Explicit edits, including clearing a name, remain authored; nonempty legacy names are also preserved. Automatic changes increment preparation revisions so concurrent edits cannot overwrite them. Vocabulary seeding must not outrank a user's saved settings during restore, and deleted rules must not reappear on reload. Suggestions never change financial rows, membership or code reservations.

Labels render locally as PNGs: the default barcode is 40 × 20 mm and the carton mark is 148.5 × 105 mm, both at 300 DPI. Code 128 bars use integer pixel widths and quiet zones; text that cannot fit or a barcode that is too dense reports an error. The black code band follows the fitted text with small horizontal padding and rounded corners, with matching clipped rounding in the editor, without changing bar geometry or physical dimensions. Carton marks emphasize CE, the base code and Chinese category while keeping the blank quantity, KG and CBM fields compact. Shared field bounds align the constrained editor with the rendered text. It commits on Enter or blur and restores saved text on Escape. A single label copies PNG plus HTML with physical dimensions; batches use one image per HTML table row. Visible preparation previews render on demand; copy and editor output retain full print resolution. Rendering uses a bounded cache and limited concurrency. Printer/scanner and spreadsheet acceptance remain separate from rendering tests.

Future workbook automation should consume validated snapshots plus preparation membership, codes and settings. Add carton measurements, loading inputs and validated freight/discount allocation before template-based XLSX generation. Reuse grouping, allocation and label rendering; do not infer identity from row position or copy formulas from historical workbooks. Direct workbook writing is not implemented in this release.

## Backups

**Back up packing** freezes every active source entry in the current preparation session, across pages and order display filters, regardless of row selection. Removed scope entries are excluded. `packing-backup.js` trims current preparation and default/previous checkpoints to those entry IDs, emits explicit v3 fields, rebuilds allocations/current ownership from that scoped state, and includes only their cached photos. Complete current source orders remain monetary dependencies, but scraped history, unrelated orders/images/allocations and extra top-level data do not. Product tags/exclusions are clipped to scoped entries; preferences contain only label artwork settings/logo and assigned tag definitions. The filename and `packingScope.months` follow the included saved groups.

Clipped product annotations use `productTagsPartialClocks` and `packingExclusionsPartialClocks` to distinguish known entries, including explicit clears, from omitted entries. Complete-order clocks retain their existing meaning. A later full restore fills omitted annotations while preserving newer local edits. Scoped preferences initialize an empty library at the existing unauthored epoch timestamp so a complete backup can supply omitted catalogs; saving Settings establishes the normal authored timestamp. Restoring a complete preparation over an exactly matching same-time subset increments its revision, invalidating stale open drafts. Conflicting shared fields or checkpoints still reject the restore.

The on-page **Save import report** action requests a fresh full job from the worker using `IMPORT_REPORT`; it validates the originating list tab/frame and reads without acquiring the import mutation lock or pumping the queue. It uses the same report formatter as Activity, with page Blob URLs released after the download request or toolbar disposal.

Version 3 backups include orders, history, notes/tags, cached pictures, preparations, allocation counters, current code assignments and packing preferences, including naming provenance, product/size/color vocabularies, logo, light/dark palettes, UI label colors and order-tag definitions/colors. IndexedDB packing preferences are authoritative; the appearance cache only avoids a flash before preferences load. Import jobs are not restored. Versions 1 and 2 remain accepted; inactive reservations in legacy files are discarded after current assignments are validated. IndexedDB version 3 upgrades the assignment index atomically without altering source orders, images, settings or jobs. Restore validates the whole file and commits atomically, preserving existing notes and newer local edits while rejecting ownership conflicts or equally dated conflicting edits. Restore resolves preparation timestamps first, then derives current ownership from the merged result; an old file cannot revive historical reservations. Active duplicate assignments abort the complete restore. Full-library backup/restore lives under **Settings → Data**; independent libraries do not coordinate numbering.

**Restore packing** lives beside Prepare in Orders, outside the shared Copy menu. Its file input cannot restore while Preparation is active. Restore previews scope and opens the saved groups without generating codes. A `packingScope` restore merges only scoped preparation entries/checkpoints, preserving unrelated membership, newer local edits and existing global settings (label settings may initialize an empty library). It reconciles tag catalogs without globally refreshing saved automatic preparation names. Passive startup, source refresh and Prepare reopening preserve matching automatic values and provenance; naming-rule changes explicitly replace automatic values, while unrelated preferences do not. Full-library restore retains its existing explicit naming recomputation. Shared group/variant edits that would alter unselected products fail atomically with an explanation; restore the full affected group/variant instead. Source-order dependencies retain normal newer-observation rules. Scope validation requires entries to exist in both source and preparation data and verifies the declared months. Both views use `mountProductCopyActions()` for identical copy-format order and header options; only Preparation adds backup.

Activity can export an `1688-import-report` JSON snapshot with extension version, discovery/save/failure counts, scanned pages and every queued order's ID, canonical detail URL, state, expected row count and error. Each failed order retains one `lastFailure` through retries, including a successful retry. Failed detail reads capture bounded financial evidence: up to 30 total fields, payable/discount summary text, product counts and aggregate amounts, and up to 25 price/quantity/discount samples with explicit omitted counts. Reports omit filters, page HTML, product descriptions/images and session data. Evidence stays local; no automatic upload occurs. Progress responses omit saved evidence; report export reads the full job directly from shared IndexedDB.

When a product discount amount cannot be parsed, diagnostics retain its exact amount text, capped at 160 characters, and source row number. An exact `包邮` badge is nonmonetary and ignored; other malformed monetary entries still fail. Failed reads also retain bounded raw financial text beside sampled values, including summary/amount/price text, to diagnose direction or duplicate-presentation problems. No tolerance is applied to unexplained cent differences; unsigned price changes require one exact reconciliation of the complete financial evidence.

Reports do not restart jobs and are not database backups. Use a backup alongside a report when analyzing imported product data. A paused scan retains discovery; completed-with-errors retry revisits only failed orders. Unknown total labels fail promptly without spending the hydration timeout, and the import continues with other orders. The 667-order synthetic regression covers 67 pages, scan interruption, independent controller recovery, partial failure and retry without rereading successful details. Real site layouts and amount presentation require separate acceptance; synthetic fixtures are not the user's database.

Removing an order also removes its history and preparation, and releases its code assignments; shared images can remain cached. Unfetched pictures require a connection. The active light/dark mode, interface language, purchase-month filter, Headers, copy-column choices and Activity read fingerprints belong to browser preferences and are not included in backups. Floating import-panel minimization is sessionStorage presentation state, separate from durable jobs. Theme palettes, badge colors and tag/color definitions are packing preferences and do enter backups. One buyer account per library is supported.

The packing row's source facts are restricted to its open scope: normalized exact unit prices and a BigInt quantity sum, without discount adjustment. Hover helpers close immediately after pointer exit; only keyboard-origin focus can keep an accessible description open.

The products toolbar uses responsive grid tracks with dedicated space for changing selection and packing-scope text. Reset tests hold a real preparation write transaction and then wait for the fieldset's native disabled property to clear before checking the action's final disabled state or exporting the saved backup. Playwright's enabled matcher does not observe disabled fieldsets, so it cannot serve as this persistence barrier.

`activity-state.js` keeps read fingerprints by job ID in localStorage, bounded to 500 jobs.
