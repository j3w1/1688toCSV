# Data model and calculation contracts

[Documentation](README.md) · [Development](development.md) · [Backup usage](data-and-backups.md)

## Sources and authored state

IndexedDB `1688-order-library` stores complete snapshots/history, order/product annotations, import jobs, image assets, preparations, allocation/ownership state, preferences and physical `cartonBatches`. Version 5 adds containers with immutable revisions, packing reports and original source assets, recoverable order carton drafts, shipment code locks and idempotent operation receipts. Earlier current-assignment cleanup remains supported. These names and file format identifiers are durable compatibility contracts despite the 1688toPL display/package rename.

All order/entry IDs are strings. Valid observations replace source only after complete reconciliation and retain prior versions. Notes, product tags/exclusions/capacities, WeChat contacts, workflow, additional charges, preparations and photo composition retain separate edit clocks. Newer edits and explicit clears survive source refresh/full restore independently of snapshot time. Partial annotation clocks distinguish omitted entries from scoped known clears. Deleting source rows does not discard annotations while the order remains.

Other-source orders carry `source: 'other'`, human `reference` and generated internal decimal ID without invented member login/shop/URL. Supplier/reference normalization is unique across the final restored library; a collision rejects the transaction. Spreadsheet identity and source-row allocations follow the [developer contract](development.md#china-store-spreadsheets). Never infer provenance for ambiguous old records.

`storeWorkflow`/`orderWorkflow` have independent clocks; `productWorkflow[entryId]` supports complete/partial annotation clocks and explicit false/none/waiting overrides. Empty product state restores inheritance. Known store/account identity alone permits propagation. `features[key] = {name,unitCost,included}` uses unique normalized authored names, nonnegative exact two-decimal yuan costs and explicit booleans. Legacy feature flags do not invent costs. Additive cost rounds quantity × per-piece once; included costs document existing evidence only.

Reviewed `paymentLinks` retain source/optional fee-row IDs, exact amount, reason, frozen receiving IDs and observed source payable/shipping evidence. New/repointed sources require same account/known store, except an eligible same-order fee. Validate final graph for cycles, oversubscription, missing references and exclusions. Receiving attribution never adds another source payment. Scoped dependencies include recursive supporting source records without opening their preparations. Repeat-product links retain shared group/variant identities and owner aliases while preserving purchase prices/quantities; identity/feature changes require unlinking, cost-only edits do not.

## Money and reconciliation

Use exact decimal/cents and BigInt helpers, never floating tolerances or inferred balancing differences. Base price may already include wholesale reductions. Round price × quantity once per source row. Allocate remaining order adjustments proportionally after item discounts with deterministic cent rounding; a price increase has a negative discount allocation. Shipping stays separate. Legacy CSV contains item discounts only; library copy includes allocated order adjustments.

Optional totals must satisfy the complete observed evidence:

- `goodsGross` is the original footer value. Row gross plus `priceIncludedDiscount` plus `grossIncludedCustomization` equals that original gross. Included values are only zero or the whole explicit wholesale/customization amounts in a uniquely reconciling supported interpretation.
- `customizationService` and explicitly signed `redPacketDiscount` stay separate; payable equals goods net + shipping + customization − red packet. Gross-included customization is excluded from goods net and added once to payable. Missing optional fields remain compatible with older records.
- Positive `商品改价` may already be in row discounts; `rowIncludedAdjustment` is zero or that whole explicit adjustment and cannot exceed source row discounts. Allocate only the remainder. Unsigned price changes test both signs, deduplicating zero, and accept exactly one complete reconciliation.
- Explicit shop/activity/cross-store reductions may be represented in rows or footer. The order-only remainder is displayed discount breakdown − price-included wholesale + row-included adjustment − row discounts. It must be between zero and the explicit shop/promotion sum; retain positive remainder as `orderDiscount`.
- A signed `元宝` reduction can contribute to the displayed discount breakdown when evidence reconciles; it is not automatically another payment deduction. Validate breakdown before payable; never fill unexplained gaps.
- Exact `外币支付手续费` placeholder `（≈）` / `(≈)` means `foreignCurrencyFeeUnspecified: true`, not zero or an exchange-fee estimate. Other unknown fee presentations remain unsupported and CNY totals must reconcile independently.

Unknown fields, installments, partial/ambiguous interpretations and inconsistent totals fail without replacing good data. Exact `包邮` is nonmonetary and ignored; other malformed monetary text remains an error. Whole-order summaries count complete matching orders once, never apportion freight/order-only discounts to filtered products, and do not label payable as paid or missing values as zero. Selection amounts use selected row evidence only.

Additional order charges retain reasons and exact allocation separately from source. Product feature and linked-payment additions remain distinct. Spreadsheet source freight/discount starts at zero because supplied unit prices already establish its agreed amount. Detailed optional export JSON retains full cost evidence independent of visible workbook columns.

## Preparation, ownership and history

Preparation groups have base code/month, source-entry membership, variants, naming/category, material and ordering metadata. Source grouping prefers structured properties, with legacy description fallback. Suggestions do not alter financial rows. New/removed source entries remain distinguishable; removed products are excluded from current labels and new entries need review.

Same-time scoped and full restores share one merger. Validated `restoreScopes` on preparations/checkpoints retains only source-entry ID sets from original restored scopes, preserving their known relative order without inventing order between disjoint scopes. Each checkpoint checks its own overlapping values and order; contradictions reject atomically. The evidence survives backup roundtrips, is clipped to retained products and disappears when a complete source supplies the full order or an authored/newer save replaces it.

Orders owns purchase/code preparation. Review allocates nothing; confirmation checks source/preparation revisions and final explicit ownership before allocating blanks in one transaction. New codes use the original purchase's literal calendar month, independently of import, assignment or shipment month. Missing or ambiguous original dates and supplier identities require explicit authored resolution; source snapshots remain unchanged, an unambiguous source wins, and disagreements remain visible. Missing sellers cannot allocate through placeholder identity. Existing issued identities are preserved rather than silently moved to a newly inferred month or owner.

An unresolved source size may retain a reviewed base product identity with a warning. Its variant barcode remains blank, unreserved and unprintable until an explicit size decision; mapping it later preserves that base. Orders, Backlog and captured output summaries retain `SIZE_MAPPING_REQUIRED` until resolution. Source date, supplier, ownership and loaded-content completeness errors remain blocking. Automatic material evidence is saved on explicit preparation/rule saves, preserves manual clears and authoring time, and is frozen with the output vocabulary.

Base format `CEYYMMGGII` uses monthly seller groups and product numbers `01–99`, continuing across purchases. Seller identity prefers source member login, with seller name as a legacy fallback; explicit missing-seller placeholders cannot allocate. Current preparations and immutable shipment code history reserve base/full codes. `activePackingState()` retains seller/month slots while dropping inactive assignments/counters; ordinary default/previous checkpoints and Undo retain values without reserving retired codes. Shared reservations hold eligible purchase aliases; unrelated duplicates reject. Restore/reset/conflict correction use the same ownership checks.

Repeat links require the same identified account/store and compatible product/variant evidence. Unconsumed purchases may explicitly reuse a code across purchase months. A positive sealed shipment permanently freezes all its lineages, including unshipped aliases, against new members; later amendments releasing all goods do not remove that lock. Drafts and zero-loaded seals do not consume identity. Codes actually referenced by historical manifests or Se quedó remain reserved independently of consumption. A legacy display-owner/canonical-supplier mismatch requires reviewed identity correction before linking, preserves issued code/prefix ownership, and remains reviewable after restore.

Suffix fields remain separate. New Variant edits reject configured size endings; Size edits reject unconfigured model letters. Configured single-letter sizes take priority, and unchanged source-derived/legacy values remain valid. Historical `suffixBaselines` exempt only exact matching field/source values, never structural/revision/ownership checks. Preview/save share validation; invalid/duplicate labels revoke their URLs immediately and stale renders cannot restore them.

Autosave waits about 800 ms and acknowledges submitted values without discarding newer typing. Valid pending edits flush before output/navigation. History retains at most 50 edits/8 MiB, coalesces typing until focus leaves and survives autosave. Multi-order corrections/removal/arrangement undo atomically after revision checks; reopening starts a new session baseline. Removal restores session-start values for prior products and unassigns new ones, saving reviewed carton consequences and scope together. Partial physical removals retain measurements/counts and flag review; empty batches tombstone.

Automatic/manual naming provenance protects explicit blanks and nonempty legacy names. Rule changes explicitly update automatic values/revisions; unrelated preferences and scoped restore do not recompute saved names. Materials use authored/suggested provenance and per-source overrides for merged rows; manual blanks survive reset/moves/restore. Local size recognition requires complete compatible axis sets; no partial/area/price inference replaces missing measurement evidence. `sizeMode: 'none'` survives checkpoints; explicit endings restore automatic mode without replacing the typed value.

## Physical cartons

`CartonBatch` retains stable `id`, `accountId`, `storeId`, `month`, `groups`, source-ID `contents`, nullable `count`/`received`/`loaded`, exact `len`/`wid`/`ht`/`weight`, `weightBasis: 'carton'|'batch'`, `suppliedCbm`, revisions/timestamps, optional provenance/review and `deletedAt`. Optional `cartonNumber` is bounded single-line text up to 40 characters and requires count one. Duplicate numbers warn without imposing uniqueness.

Optional `mark: {orderId,groupId}` is independent of contents, including zero-piece mark owners. Legacy fallback uses the first group only when explicit mark is absent; freeze fallback before removing legacy owner groups. Current writes have exactly one source purchase, even when purchases share product codes. Legacy cross-order evidence remains inspectable and requires review; it is never permission to create another cross-order carton.

Order-owned operational batches retain `orderId`, optional compatibility `month`, `packingBasis: 'exact'|'uniform'|'aggregate'`, independent `volumeBasis`, reported/internal label provenance, nullable unresolved candidate quantities and source/manual evidence. They need no prepared group merely to save supported physical facts. `contentsUnknown` is not zero. Reviewed entitlement indices and explicit per-unit contents preserve physical identities when a report changes; aggregate totals never imply variant distributions. Derived Backlog uses eligible source quantities less effective shipments, distinguishes draft reservations and holds ambiguous legacy loading for review. Unknown box counts do not inflate known totals.

Dimensions are complete positive xyz or all blank; volume is exact product / 1,000,000. Confirmed dimensions supersede supplied CBM in measured totals. Explicit set dimensions apply to each physical unit unless that unit has separately confirmed dimensions. A unit supplied-CBM exception remains supplier evidence; it does not replace inherited confirmed dimensions. Its warning identifies the unit and offers separate measurement to review the difference. A difference retains the original supplied value and its per-carton or batch basis, and displays a nonblocking warning with both totals and the measured value used in Orders reconciliation, container seal review and XLSX/JSON exports. Ambiguous units or bases and quantity, count, ownership or source contradictions remain errors. Per-carton weight multiplies confirmed count; batch-total weight is known for zero or full batch only, never prorated for partial received/loaded counts. Unknown versus zero is preserved and confirmations do not alter product receipts. `cartonProductPacking()` establishes capacity only from full uniform exact evidence or explicit matching single-product aggregate contents/counts, not divisibility.

Pre-v4 upgrade converts historical defaults once in its upgrade transaction; backup v1–3 retains legacy conversion. Runtime `createLegacyCartonBatches(..., {physicalEvidenceOnly:true})` accepts explicit boxes/confirmations and never derives physical counts from capacity-only or measurement-only defaults. Stable `legacyKeys` prevent duplicate shared-source totals; tombstones prevent reseeding. Source annotations remain evidence without another physical total. Source refresh preserves allocations and projects review issues for reduced/missing products/context. Legacy loaded counts do not create verified shipments; ambiguous loading and cross-order records remain held for explicit review. Review can correct an explicitly confirmed single owner without renumbering the physical batch, or retire the original after an explicit physical-repack attestation. Retirement retains its original mixed contents/counts/measurements in history and returns goods to source unassigned pools; it never manufactures replacement boxes. Record the new single-order cartons through normal Orders confirmation.

Stable indexed unit contents and measurements support a physical exception without renumbering untouched cartons. A formerly declared uniform set retains the untouched proven facts. A changed content weight becomes stale until explicitly reconfirmed; original reported facts remain in history. Genuine aggregate evidence cannot be divided to fill unknown units. Reconciliation preserves known measurement subtotals and missing coverage independently of complete-set totals.

Source reconciliation carries all independently authored inventory/identity values, clear markers, edit clocks and metadata history into the new record. Source changes conflicting with an existing exclusion reject for explicit review. Source refresh and restore also validate the effective shipment graph in the same transaction: a positively shipped source row cannot disappear or fall below its committed eligible quantity. Rejection retains the prior source/history and cannot poison unrelated edits or seals.

The shared transaction guard also covers legacy order-writing APIs, including single and bulk payment links: shipped goods cannot become an ineligible payment source after sealing. A source reduction conflicting with a draft's captured reservation rejects as well. Remove the named order from that draft, refresh and review its source, then include its current remainder again.

Local change subscriptions invalidate views only after successful commit. Their database-scoped messages contain schema, sequence and store names, without order identifiers or values. Aborted transactions and read-like export/list calls emit nothing. Unsubscribe, connection close, version change and page exit release the channels. A missed or duplicated notification never replaces transaction/revision checks: dirty inputs and captured amendment epochs still require conflict review.

## Containers, reservations and historical output

Backlog is a derived projection of eligible purchase quantities less effective shipments. Explicit non-goods, fee, payment-only and canceled dispositions retain authored evidence and independent edit clocks; a legacy UI skip does not establish a goods exclusion. Unknown physical counts remain unknown. Draft-reserved goods stay visible with their container reference. Se quedó is the frozen remainder of included orders at one shipment revision, not current global Backlog.

Whole-order inclusion captures the available remainder and evidence revisions without loading it. Draft reservations protect both known cartons and goods awaiting packing evidence. New source/cartons do not silently enter an existing container; availability changes require review. Loading uses stable physical identities, deriving product quantities once. Count selection is available only for truly interchangeable contents and measurement behavior. Partial aggregate loading retains unknown contents/combined measurements; numerical equality with a purchase is not complete-set coverage evidence.

Seal validates current source, physical facts, reservations and loading in one transaction. Unknown loaded product totals, stale evidence and loaded-scope contradictions block it. Missing kg/CBM is disclosed and may pass when quantities/counts are verified. Success freezes source prices, codes, names, photos, physical evidence, preferences and full logical output membership; loaded entitlements become exclusive and remaining draft reservations release. Repeated operation intents are idempotent; unrelated stale edits reject with drafts retained.

An amendment leaves the previous effective shipment active until an atomic reviewed apply. Cancel changes no effective allocation. Apply checks other effective shipments/reservations, creates a distinct immutable revision and preserves all earlier manifests and Se quedó. Report/carton corrections to historically used facts stage in that amendment rather than replace effective history. Source deletion remains blocked while active or historical containers need it.

Loaded money retains exact source-line prices and allocated source cents. Partial shipment allocations reconcile to source adjustment/freight totals without copying full charges into every shipment; amendments preserve other effective manifests and their allocated cents. Shared codes keep independent financial rows. Export and print adapters consume the chosen frozen revision, preserve unknown physical facts and label product kg/CBM attribution as allocated. A live name/photo edit cannot replace historical output assets.

## Images and archive transport

Original local rasters use content-addressed `local-image:<sha256>` with gallery associations. Photo edits retain separate composition, normalized dot/label coordinates, unique IDs, tags (up to 50; text 1–64 single-line characters), tag/pointer scales and inversion. Defaults for new edits are 200%/100%; legacy rendering defaults remain 100%. `setProductPhoto()` verifies the original reference, cloned drafts preserve Cancel, and transform changes reproject points without allowing a crop to hide one.

Loading, cache and backup selection share canonical remote identity: thumbnail suffix normalization must select the cached original. Full backups collect references from retained orders/history/owners and omit orphan cache entries. Scoped backups retain required source/local originals and relevant canonical cached photos. Do not replace originals with embedded workbook thumbnails or remove source history to save space. Workbook-wide media payload reuse and generated-artwork caching preserve repeated visible cells without duplicate embedded bytes; PDF resources avoid per-page complete-table duplication.

`backup-file.js` uses `1688-order-library-archive` v1: inner v1–5 `backup` with null image leaves plus `assets` containing each exact `dataUrl` once and typed occurrence paths. Array indices differ from object keys; own-property paths must target null leaves without duplication. Decode/decompress to completion and validate paths before expansion/atomic repository validation. `createBackupBlob()` streams separately serialized metadata/assets through native gzip; periodic yields support the browser baseline. Compression is transport, not a new database schema or live image migration.

Scoped restore merges only declared entries/checkpoints, preserving unrelated/newer state. Same-time disjoint fragments may complete missing data when shared fields and checkpoints agree; contradictions reject. Revision increments invalidate stale drafts. A scoped-initialized settings record differs from an empty seed so later scoped restores preserve it; full restore can fill omitted catalogs by normal precedence. Label-only scoped settings never imply authored global vocabularies. Full restore validates current ownership, graph dependencies, physical completeness, duplicate manual identity and annotation clocks before committing anything.

`removeOrders()` checks active contents/groups/marks and financial references inside its write transaction before deleting source/history/preparation; unused assignments release while shared owners survive. Batch tombstones remain. Browser preferences/import jobs remain outside restored library payloads. See [backup scope](data-and-backups.md) for user-visible omissions and retention.

## Import diagnostics

Durable job checkpoints track discovery, detail stage/start/attempts, current/saved rows and latest result. Only saved/failed checkpoints advance processed counts; retries do not double-count rows. Reader progress verifies owned tab/frame/job/order without the mutation lock and does not pump jobs. Activity updates existing nodes, not full library reads. Elapsed time is not progress/ETA. Read fingerprints are bounded to 500 jobs; normal ticks do not mark unread. Dismissal hides nonrunning history without deleting records.

`1688-import-report` exports IDs, canonical URLs, states, expected rows, counts/errors and latest bounded failure evidence, retained even after successful retry. Financial evidence caps at 30 fields and 25 samples, with omitted counts; malformed discount text caps at 160 characters plus row number. No page HTML, descriptions/photos, filters or session data enters the report. Export is read-only and never restarts jobs. Unknown totals fail promptly; other orders continue. A 667-order/67-page synthetic controller case is scale/recovery coverage, not live collection acceptance.
