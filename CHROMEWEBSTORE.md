| Theme palettes and UI label colors                                                                | Authoritative local settings included in backups                        | None                                                                     |
| Active mode/language, filters, copy choices, Activity read state and minimized panels             | Local browser preferences; minimized state lasts for the tab session    | None                                                                     |
| Supported URLs/filters                                                                            | Explicit import and retained checkpoints                                | Requests to 1688 to load those pages                                     |
| Authentication information                                                                        | No password/token/cookie extraction                                     | Normal navigation uses the signed-in browser session                     |

Orders, purchase dates, histories, notes/tags, product packing exclusions, jobs, images and preparation data persist locally. Cached images are deduplicated by URL. Removing an order removes its versions and preparation, releases its code assignments and may leave shared images cached. Dismissing a job hides its notice while retaining the record. Version 3 backups include orders/history/notes/tags/cached images, preparations with ordering and restore checkpoints, allocation counters, current code assignments and packing preferences with naming/size/color rules, label settings, palettes, badge colors and tag definitions/colors. Active jobs are not restored. Version 1 and 2 backups remain supported; legacy inactive code reservations are removed after validation. Scoped packing backups retain complete current source orders, scoped preparations/checkpoints, selected-product photos, current assignments and label settings/logo with assigned tag colors; they omit scraped history and unrelated global catalogs or allocations; restoring them preserves existing global settings, while their settings may initialize an empty library. Conflicting current ownership rejects restore atomically; older backups cannot revive retired assignments or overwrite newer preparation values.

Import reports save queued order IDs, canonical detail URLs, statuses, expected row counts, errors, run counts and latest failed-read financial evidence on request. Evidence is bounded to 30 total fields, 25 product financial samples and aggregate amounts, with omitted counts. Invalid product discounts retain amount text capped at 160 characters and source row number. Reports exclude page HTML, product descriptions/images and session data. Retries retain the latest failure after success. No automatic upload occurs. Local search reads existing source/display values and rules without transmitting queries.

Active light/dark mode, interface language, purchase-month filters, Headers, copy-column choices and Activity read fingerprints are browser preferences, separate from backups. A floating import panel's minimized state is stored for its browser-tab session and does not alter durable jobs. First-use defaults are dark, English, current purchase month and Headers off. Packing month starts at the current month whenever the workspace opens. Uninstalling or deleting the profile can delete the library. Clipboard data and saved files are subsequently controlled by the operating system and user.

Automatic naming uses bundled generic title rules and user-edited rules. Suggestions are retained locally on import, restore and existing-library updates, independently of source amounts and issued codes. Field authorship preserves manual names, including intentional blanks; unknown products remain unnamed. Size rules use local literal aliases and SKU/description measurements; product titles and article numbers do not establish sizes. Ambiguous assortments remain reviewable, and manual size mappings remain intact. Matching-order totals read saved financial data locally without extra network requests.

### Known limitations

- One buyer account per library; no automatic account detection.
- Unsupported layouts, installment totals, unknown adjustments and inconsistent totals report errors and preserve good saved data.
- Bulk images use standard-height Excel rows and are floating pictures. Custom row heights, other spreadsheet apps and native in-cell conversion need separate verification.
- Cached images work offline; unfetched images still need a connection. Large uncached copies can take time.
- Packing suggestions need review, especially missing structured SKU data or ambiguous sizes. Local naming rules are not general translation; unknown products stay unnamed and conflicting fields stay blank.
- Current code assignments belong to the local library and its backups; independent libraries do not coordinate numbering. Changing or removing an assignment releases its old code, including previously copied labels. Undo/reset checkpoints do not reserve old codes, and restore checks current conflicts. Group moves stay within an order, and product moves stay within a group.
- Version 2.2.0 label pasting and Excel picture dimensions were verified; physical printing and hardware scanner use remain unverified. Direct workbook population is not implemented.
- Legacy CSV preserves item discounts; library copying also allocates order adjustments.
